# 미반영 고려사항 — record-actions-code 분자 (넣을까 말까 결정용)

작성 2026-08-31 (§66~§68 감사 직후). 기준 표본: 이 PC 최근 55세션(200KB 초과),
분모 13,812분. 현재값(§75 후) **ON/ON 79,805분 6.11배 · OFF/OFF 112,532분 8.61배** (분모 13,063분).
기대효과 %는 그 조합의 현재 분자 대비. 재측정은 `bench_4combos.py`(고정 목록, 같은 폴더) 방식 —
§7.1 표와 같은 절차로 4조합 전후 + 역전(ON>OFF) 세션 수를 함께 낼 것.

전제 두 개 (변경 금지):
- 분자는 ON·OFF 모두 **해당 업무 숙련자** 기준. OFF = 숙련자가 AI 기록을 그대로
  재연, ON = 자기 방식. "숙련자도 했을 일인가"로만 판정한다.
- **항목별 ON ≤ OFF**. OFF만 올리는 항목은 안전, ON만 올리는 항목은 OFF가
  상한, 공통 가산은 순서 불변.

## 이번 감사에서 **넣지 않기로 확정**한 것 (재검토 불필요)

- "코드 이해 시간을 고친 코드량에 비례해 추가" — 분자는 숙련자 기준(문서 §3)이라 평균 개발자 문헌(Xia 58%)을 목표로 삼는 것은 자의 목적 오인. 철회.
- "ON > OFF 허용" — 불변식 위반. 철회.
- `subagent_type`(Plan/Explore)별 요율 차등 — 통로 이름으로 면제/차등하는 데서 구멍이 났던 §59 교훈.
- 문서 78% 정독 0 · 검색 40회→1건 · 헛읽기 0 · 반복 명령 작성 0 · 썼다 지운 글 0 — 숙련자는 안 하는 일. 설계 의도.
