diff-effort — 코드 변경 라인 → 사람 노동 환산

저장소에서 보정 비율을 재고(1), 사용량 CSV 를 넣으면(3) 사람별 노동 시간과 효율 지표를 낸다(4).

이 계산은 실측 두 개 위에 서 있다. 둘 중 하나라도 없으면 나온 값은 노동시간도 효율도 아니다.
아래 상태는 지금 고른 설정·CSV 기준으로 실시간 갱신된다.
확인 전 ① 코드·문서·데이터 구성비 안 재면 문서·데이터까지 코드 요율로 쳐서 사람노동(effort) 자체가 부풀려진다. 1·2 칸에서 잰다. 대상 세션의 저장소를 못 쓰면 성격이 비슷한 예시 프로젝트로 대신 재서 개략 추정값을 얻어라 (1 칸의 "예시 프로젝트로 대신 잼"). 그 값은 추정이지 실측이 아니다 — 보고할 때 그렇게 밝혀야 한다.
확인 전 ② 사람 개입시간 (user_active_sec) 사람이 실제로 붙어 있던 시간. 효율 x_user·x_total 의 분모다. 안 재거나 0 이면 효율을 낼 수 없다. 3 칸의 CSV 에 들어 있어야 한다. CC 시간의 10% 미만이면 계측 누락으로 본다.

1 비율 잴 대상 저장소

    아직 고른 저장소가 없다. 위에서 git 표시가 붙은 폴더를 누르면 담긴다.
    대상 세션의 저장소에 접근이 안 되면, 성격이 비슷한 예시 프로젝트를 골라 대신 재라. 개략 추정값은 나온다. 단 그 값은 추정이지 실측이 아니다 — 체크해두면 ratios.json 과 리포트의 [가정] 블록에 "대리 측정(추정)" 으로 박히고, 위 전제 칸도 노란불로 바뀐다.
    저장소당 몇 초 걸린다.

    1 비율은 이 서버에 고정돼 있다

    저장소 선택·측정은 이 화면에서 막혀 있다. 브라우저는 당신의 PC 에서 git 을 돌릴 수 없고, 이 서버가 뒤지는 건 당신 PC 가 아니라 서버 자신의 디스크이기 때문이다. 아래는 관리자가 미리 재둔 값이며, 잰 저장소는 git 원격 주소로만 표시된다.
