## 1. 분자 재개발 — 방법론 v0.5→v0.6 (human-effort/requirement-based)

- 3계층 분리 구현: LLM은 수량만 / catalog.json이 시간분포 / 코드가 Monte Carlo로
  P50·P80을 최종 분포에서 1회 산출. LLM의 시간 출력은 검증기가 재귀 제거.
- **인플레이션 사고와 통제** (메일 회신 338.8분 → 16.1분, 상세: doc/DESIGN.md §2.3):
  - 기준 노동 명문화: 배제는 생성형 AI뿐(도구 전부 사용) + 합리적 최단 경로
  - 요구사항 발명 금지(중간 활동의 산출물 승격 차단), 분해 상한, 습관성 QA 금지
  - 경량 Work Unit 6종(잔일 보기), 수량 단위 일치 강제, conflicts_with 중복 제거
  - "자동화→시스템 구축" 오독 차단: 운영/구축 구분 + SW 라우팅 교차검문
    (RCA 세션 3연속 SW 항목 0건)
  - Pass D(독립 재검토, 깎기만 가능) — critic=True 옵션
- 입력 케이스 분리: 아바타 정의서(A-avatar, 변환)와 트랜스크립트(§23, 복원)를
  별도 1단계로, 2단계부터 공용(estimate_from_requirements).

## 2. 구조 재편 — efficiency/ 통합과 용도별 API

- human-effort(분자)·agent-effort(분모)·counterfactual-api(아바타 사전 API)
  + session-api(세션 사후 API, 신설)로 정리. 규칙: 부품 + 용도별 조합.
- 분자 방식 3종을 이름·폴더로 분리 (혼동 방지):

| 공식 이름 | 폴더 | 흐름 |
|---|---|---|
| **요구사항·산출물 방식** (기준 자) | `human-effort/requirement-based/` | 할일 추출 → 산출물 단위(명사) × 카탈로그 분포 → Monte Carlo |
| **요구사항·행동 방식** (신방식) | `human-effort/requirement-actions/` | 할일 추출 → 사람 행동(동사) × 요율, 숫자는 닻으로 코드 확정 |
| **세션기록·행동 방식** (교차확인) | `human-effort/record-actions/` | 기록 신호에서 바로 사람 행동 시뮬 × 요율 (+하이브리드 옵션) |

공용 부품(할일 추출기·정규화·LLM 시뮬)은 `human-effort/shared/`.

## 3. 분모 측정 기조 확정 (agent-effort)

- 프레임: **사람·AI 협업의 양측 에포트를 같은 단위(분)로 합산**
  — agent_min = 사람 감독(hitl) + AI 실소모.
- hitl은 wall-clock이 아니라 **단서 × 요율** (검토·후작업은 세션 밖에서 몰아
  할 수 있어 세션 시간으로 못 잡음). 타임스탬프는 요율 값 보정 재료로만.
- 병렬 서브에이전트는 실소모 시간에 가산 금지 (자원량 옵션만).
- 분모는 LLM 0회·결정론 (죽은 LLM 주소로 실행 증명).

## 4. 요율 실측 보정 1호 — hitl.instruct (rates.json)

- 트랜스크립트 타임스탬프(직전 응답→지시 간격) 1,456건 분석: net 중앙값 0.61분,
  구 3.0분/건은 2~5배 과대. 100단어+ 지시는 붙여넣기 증거로 상한 필요.
- 실측 경로: `instruct = 0.5분(생각 여유) + 0.05분 × min(단어수, 60)`,
  사전 경로: 건당 1.7분(실측 평균). 효과: 6세션 종합 speedup 2.38→3.22x.

## 5. 신호 체계 — "어떻게 했나"는 빼고 "뭐가 만들어졌나·요구됐나"는 넣기

정규화(shared/transcript_requirements)가 기록에서 결정론 추출하는 신호:
- [산출물 규모] 작성 단어 순계 (반복 재작성 중복 제거)
- [입력 자료 규모] 사용자 제공 텍스트량 / [조사 자료 규모] 검토된 자료량(상한 명시)
- [대화 보고 규모] 파일 없으면 보고가 산출물
- [작업 구조 참고] 검토 파일 목록·탐색/실행 여부·지시 왕복 — 횟수 베끼기 금지 경고
- 도구 사용 통계는 기본 제외 (경로 베끼기 오염 실측 확인; 규모 신호 없이는
  측정 붕괴도 실측 확인 — 13.8h 작업이 54분)

## 6. 숫자 닻 — 편차 제거 (requirement-actions)

- LLM은 행동 종류만, 규모 숫자는 코드가 확정: 쓸 단어수=요구 명시 분량>실측
  산출물, 읽을 단어수=실측 검토 자료량, **검증 건수=완료조건 개수**.
- 효과: 반복 실행 편차 ±0.1~4% (닻 이전 수 배). 이중 추출 대조안은 LLM 비용
  2배라 기각.

## 7. 용어 A/B — "요구사항" → "할일(완성해야 할 결과물)"

- '요구사항'은 SW 명세 프레임을 깨워 격식 과잉 유발(완료조건 17개 발명).
  '할일' 문구로 11개로 감소, 조사형 견적이 기준 자에 수렴, 악화 유형 없음.
- 프롬프트 표현만 교체, 스키마 필드명(requirements.v1)은 규약 유지.

## 8. 실측 대조 자산 (네 PC 세션 14개)

- 분자 두 자 대조: 합산 0.98배 수렴하나 유형별 0.2~2.7배 계통 괴리 —
  유형별 신뢰 자 규칙(문서·채점형은 요구사항·산출물 방식, 코드형 병행).
- 하이브리드(요구사항+기록) 실측: 조사형 0.64→0.88배 수렴, 악화 없음.
- 카테고리 10종 중 6종 실사용 확인, 카테고리별 단가 최대 75배 → 오분류 방지
  장치가 핵심 통제임을 재확인.

## 미해결 (알려진 한계·다음 단계)

1. **사람 실측 정답지 0건** — 모든 절대값의 상한. A급 3~5건 확보가 최우선.
2. 단위 눈금 양끝: SW 잔수정 단위 추가(작은 쪽), 대형 견적 검토 딱지(큰 쪽).
3. AI 장황함: 문서 대량 생성형은 어느 자로도 부합 불가 — 요구사항·산출물 방식 기준.
4. 판단 깊이: 건당 고정 시간이라 채점형 과소 잔존.
5. review·correct 요율 미보정 (instruct와 같은 방법으로 가능).
