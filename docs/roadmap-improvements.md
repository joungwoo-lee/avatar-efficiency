# 추가 개선 방향 (로드맵)

관련 연구 조사([paper.md](paper/paper.md) §2)와 구현 과정에서 도출된 개선 후보 정리.
✅ = 구현됨, 🔜 = 저비용 우선 대상, 🔶 = 중간 비용, 🔷 = 무거움(실험·운영 포함).

## 1. 매칭·측정 품질

| 항목 | 내용 | 근거 문헌 | 상태 |
|---|---|---|---|
| 세션 요약 경유 매칭 | 저지가 workSummary(실수행 요약)를 항상 출력 → 분류 안정·감사 기록 | Clio | ✅ 2d2178c (동일 콜 통합) |
| 기타 업무 수집 | 미매칭을 `misc`로 송신, 신규 업무 설명 부착 | Economic Index | ✅ 2d2178c |
| **misc 클러스터링 → 업무 제안 자동화** | 서버가 misc workSummary들을 주기 클러스터링해 "아바타 정의에 추가할 업무 후보" 리포트 생성 — 트리 노후화 방지 피드백 루프의 완성 | Economic Index | 🔶 |
| **감독시간 분리** | H_active를 "에이전트 실행 구간"과 "인간 개입·검토 구간"으로 분해(턴 타임스탬프로 코드 계산) → V 식의 ρ_sup이 실측이 됨. 대기·검토가 진짜 비용이라는 METR 통찰 반영 | METR 2025 | 🔜 |
| **bottom-up 노력 추정** | η 분자를 홀리스틱 1회 추정 대신 "산출물 나열 → 앵커별 시간 → 합산" 분해 강제 — 전문가 추정 문헌의 검증된 개선책 | Jørgensen | 🔜 (프롬프트 수정만) |
| **아티팩트 증거 채점** | transcript에서 커밋 해시·수정 파일·테스트 결과를 코드로 추출해 `evidence` 필드 부착, 저지 quality 채점을 증거 기반으로 강제 — "말 잘하는 세션" 우대(verbosity bias) 차단. 추후 PR/DORA 데이터와 조인해 ground truth 확보 경로 | Zheng, SPACE/DORA | 🔶 |

## 2. 저지(judge) 신뢰성

| 항목 | 내용 | 상태 |
|---|---|---|
| **judgeModel 기록** | 레코드에 사용 모델 버전 필드 추가 — `claude -p`는 모델이 조용히 바뀌므로 드리프트 추적의 전제 | 🔜 (필드 1개) |
| **고정 감사셋** | 동일 세션 N개를 모델 업데이트 시마다 재채점해 저지 드리프트 감지. 감사셋 채점 이력을 서버에 별도 보관 | 🔶 |
| self-consistency | 고가치 세션(η 상위, 코스트 큰 업무)만 저지 2~3회 반복 → 중앙값 채택, 분산을 confidence로 기록 | 🔶 (토큰 비용 증가) |
| calibration 보정계수 | §7 캘리브레이션 실험에서 얻은 업무별 실측/추정 비율을 per-task 보정 승수로 환류 | 🔷 (실험 선행) |

## 4. 프라이버시·운영 건전성

| 항목 | 내용 | 상태 |
|---|---|---|
| PII 스크럽 | 서버로 가는 rationale·workSummary에서 이메일·경로·키 패턴 마스킹 | 🔜 |
| k-익명 집계 | 서버가 n≥k에서만 개인 식별 가능 지표 노출, 기본은 팀 단위 집계 — 단일지표 Goodhart 경고 대응 | 🔶 (서버 정책) |
| 게이밍 탐지 | η 급등·rationale 이상 패턴 플래그, 앵커를 검증 가능한 산출물에 결박. 측정과 인사평가의 제도적 분리 권고 문서화 | 🔷 (조직 정책 포함) |
| 동의·고지 절차 | setup 시 수집 범위(파생 레코드만 송신, 원문 비전송) 고지·동의 화면 | 🔜 |

## 5. 평가(논문 §7과 공유)

1. 매칭 정확도: 라벨 세션 ≥300건, per-task P/R, no-match 동작점, script 구체성 ablation
2. η 캘리브레이션: 전문가 추정 + 실제 수작업 재현 실측 대비 MAE·순위상관, 앵커 유무 효과, 저지 모델 민감도
3. 종단 배포 8–12주: E 추이 vs 자기보고·DORA, 공정성·게이밍 인터뷰
4. 비용 충실도: 구독 환산 vs API 실측 과금 비교

## 권장 착수 순서

**1차 (저비용 즉효):** 감독시간 분리 → bottom-up 추정 프롬프트 → judgeModel 기록 → consumer 검증 → PII 스크럽 → 증분 재매칭
**2차 (구조 확장):** misc 클러스터링 제안 → 아티팩트 증거 → provider HTTP → 중앙 서버 + k-익명
**3차 (연구·규모):** 감사셋·캘리브레이션 환류 → 멀티 에이전트 → 평가 4종
